## Gotchas

- `BackEnd/demo_cache/` is gitignored, so a fresh clone has no cached results and the first upload of each test image calls Gemini. The prescription test image's cache entry (`a7618b30...json`) was lost once; it was restored from git history (`git show 54a4ffe:BackEnd/demo_cache/a7618b30e5a763ed0378a69a2e6d3a4c8d22f7daeaef68bb3c3019187f0e2ffc.json`). Gemini's free tier hits 429 quickly, so keep these cache files.
- `scripts/smoke.py` and `POST /api/demo/reset` act on the DB the server points at (Supabase when `DATABASE_URL` is set) and wipe Ammini's uploads, imports and visits.
- Gemini rejects client deadlines under 10 s (`HttpOptions(timeout=...)` is in milliseconds).
- `.env` was committed once in git history (commits `c22276f`..`22c0e01`) but was empty; no key, token or password appears anywhere in history (checked in Phase 6). `uploads/` and `demo_cache/` fictional test files are also in early history.
- `main.jsx` renders under `<StrictMode>`, so every effect mounts twice in dev. Effects that start timers must keep progress in a ref and re-arm after cleanup (the demo auto-feed in `RecordingPanel.jsx` was broken by a `fedRef` guard).
- `Alert.kind` values in use: `interaction`, `duplicate`, `clash`, `allergy`, `lab`, `trend`. `severity` is `high | medium | low`; `resolved=false` means open.
- `Document.type` values: `lab`, `prescription`, `consultation`, `visit` (console approve and FHIR encounters), `scan`. Add new types to `i18n.js` or the card shows the raw key.
- The offline build (`build:single`) is mock-only and uses hash routes. In code, build links with `appPath()` / `appUrl()` / `goLogin()` from `src/routing.js`, never a bare `/path` or `window.location.assign`.
- Claude-in-Chrome cannot open `file://`. To test the offline file, serve `dist-single` with `python3 -m http.server`, and use headless Chrome (`--dump-dom file://...`) for the `file://` check. To audit layouts at 390/1024 px, load routes in fixed-width same-origin iframes and set `documentElement.dataset.theme` to `light` or `dark` (OS dark mode is otherwise what you get).
- A dev backend started with `uvicorn --reload` picks up code edits but not env changes; restart it to change `DEMO_MODE` or `CORS_ORIGINS`.

- `DATABASE_URL` must be the Supabase session pooler URL (`*.pooler.supabase.com`). The direct host is IPv6-only and fails on this network. If Postgres is unreachable the backend falls back to `BackEnd/medithread.db` (SQLite).
- Redis is optional; without it OTP and reminder-taken state live in memory and reset on restart. Dose dedup does not depend on Redis: it is also written to `sent_doses`.
- `add_missing_columns()` (app/database.py) runs at startup and ALTERs new nullable model columns onto existing tables, so upgrading a Postgres DB no longer needs `RESET_DB=1`. It only adds columns; it never changes or drops them.
- Run exactly one backend process with the scheduler against a given DB. Two processes (for example a `--reload` server plus a second `uvicorn`) each run a scheduler and can both send the same dose in the same second. `uvicorn --reload` hot-restarts on any edit under `BackEnd/`, so it also picks up new code and re-runs the startup migration.
- Telegram: the bot token and chat ids are never logged. Errors returned to the UI are plain-language (`ai/telegram.py::send_to`). With `TELEGRAM_BOT_TOKEN` blank the server still starts, the scheduler sends nothing, and `GET /api/reminders/settings` returns `telegramReady: false` (camelCase, like the rest of the API). A chat ID must be numeric (`^-?\d{5,20}$`); the user gets it by messaging the bot first.
- `DEMO_MODE=true` (env, not set by default) enables `/api/demo/fire-reminder`, `/api/demo/fire-missed`, `/api/demo/reset` and `/api/health/deep` (all need a login, 404 otherwise) and makes the settings response return `demoMode: true`, which shows the "Demo controls" card on the Reminders page.

## Phase 10 — voice, visit classification, handwriting (in progress)

**10.1 Speech-to-text (done).** The browser's Web Speech API was the accuracy ceiling (Indian accents, drug names, Malayalam), and the mic never auto-started (doctor had to press "Resume mic"). Now:
- `POST /api/consultations/{id}/audio` (multipart `file`, `speaker`, optional 2-letter `language`; `X-Share-Token` like every other consultation call; 6 MB cap; type checked by magic bytes, never the client's content type). It runs `ai/transcribe.py` (Groq Whisper `whisper-large-v3`, override with `GROQ_STT_MODEL`) and feeds the text into the same `_append_line` pipeline as typed lines (flags, partial SOAP, suggestions). `add_line` was refactored onto `_append_line`; behaviour unchanged.
- Whisper invents text on silence/noise ("Thank you."). `verbose_json` segments are filtered: phantom phrases, `no_speech_prob > 0.6` with `avg_logprob < -1.0`, `compression_ratio > 2.4`. Silence returns `added: false`; nothing is added to the transcript.
- Drug names: the Whisper prompt is primed with the patient's active medicines + common Indian brands (`medterms.common_brands`). After transcription `ai/medterms.py::correct` fixes near-miss medicine names (e.g. "glycum" -> Glycomet) **only** in sentences with prescribing context, only for words that are not already known medicines or ordinary English, tier 1 (patient meds + `BRAND_TO_GENERIC`, loose match, same first 3 letters) then tier 2 (DDInter `drugs`, close match). Every change is returned as `fixes: [{from,to}]`, stored on the line (`line.fixes`) and shown as an amber "✎ heard → corrected" mark in the console transcript. Never silent.
- Frontend: `useWhisperRecorder.js` runs ONE MediaRecorder on one mic stream with an RMS voice-activity detector (adaptive noise floor). It cuts a clip after ~0.9 s of silence (or 14 s), starts the next recorder immediately (no lost first word), discards clips with no real speech, and uploads strictly in order with retry. `RecordingPanel.jsx` starts listening automatically (not for the scripted demo), shows Hearing / Transcribing / Listening, has an Auto/English/Malayalam hint, and "Stop and review" now awaits `flush()` so the last sentence is not lost. Browser recognition keeps running only as a live caption, and becomes the engine automatically if Whisper answers 503 (no key / free-tier limit) or in the offline mock build.
- Gotchas: `useWhisperRecorder` guards double `start()` (StrictMode) with a `starting` flag and a `mounted` ref. `run_consultation.py` defaults to `RESET_DB=1` and wipes the DB it points at (Supabase when `DATABASE_URL` is set): do not run it casually. Test accounts for audio checks: register `stt-<hex>@example.test`, then `scripts/cleanup_test_accounts.py <email>` (it only removes smoke-/sweep-/edge- prefixes plus emails you pass).
- Tests: `scripts/test_stt.py -v` (15 cases, no network). Live check done with macOS `say` -> WAV: real speech transcribed ("Glycomet" heard correctly after prompt priming), 3 s of noise rejected, junk bytes 415, no token 401.

**10.2 Visit classification (done).** Before this, `/approve` found medicines with a regex over KNOWN brand names only (unknown drugs dropped, "stop X" could create X), and nothing classified diagnoses, tests or advice.
- `ai/visit_classify.py::classify(lines, active_meds)` (Groq, one call at `/finalize`, run in parallel with the SOAP call) sorts the transcript into `complaints, diagnoses, medicines, tests, advice, referrals, follow_up, ignored_lines` and stores it at `final_note["classification"]`. Small talk is excluded and listed in `ignored_lines` (health talk, even unprescribed, is never "ignored"). The SOAP prompts also ignore loose talk now.
- **The model proposes, code decides** (`validate`): every item needs valid source line numbers; diagnoses, medicines, tests, advice, referrals and follow-up must cite a DOCTOR line; items must share real words with the lines they cite; dose is kept only if the number+unit is in the cited words; frequency/timing/duration are nulled unless a cue word is really there. Cues are checked only in the words from THAT medicine's name to the next medicine's name (`_own_words`): one line often holds several medicines, and one's "morning" must not justify another's timing. Missing detail stays missing.
- `/approve` body has `removedItems: {medicines:[i], diagnoses:[i], ..., follow_up:[0]}`: INDEXES into what the server stored, so the doctor can drop items but nothing can be added from the browser. Removed items are kept in `final_note.classification.removed` for audit. Medicines come from the classification (unknown drugs included, `generic` may be null): `start` adds, `continue` adds only if not already active (no duplicates), `change` switches the old one off and adds the new one, `stop` switches the matching active medicine off (reminders stop). The response has `classification` and `stoppedMedicines`.
- Frontend: `VisitClassification.jsx` (shared). Review screen: sections with Source buttons (highlight transcript lines) and a remove/undo per item. Approved screen: read-only "What was recorded". Offline build has a sample (`mockClassification`).
- **Groq limits and failing safely.** The free tier is **8,000 tokens/minute and 200,000 tokens/day, per model**, and `max_tokens` is reserved up front. A day of testing exhausted the daily budget (`RateLimitError` with "tokens per day"), which silently pushed visits onto the fallback and made approve hit nginx's 90 s limit (504), because the Groq SDK retries 429s twice honouring `retry-after`. Now: the consultation and transcription clients use `max_retries=0` (fail fast); `_chat_json(wait_on_limit=, fallback_model=)` is used only by the one-off `/finalize` calls: main model rate-limited -> try `FALLBACK_MODEL` (`openai/gpt-oss-20b`, its own quota; grounding checks still apply) -> if Groq says the wait is short (<= 8 s) wait and retry the main model -> never wait out a daily limit. Live per-line calls never wait or fall back. Finalize and approve each take about 2 s. `doctor_ai.py`, `health_review.py`, `translator.py` still use default SDK retries.
- **Fallback when the AI is unavailable** (both models limited, or Groq down): the review screen says so, and `/approve` uses the old plan-text extraction, now cautious: sentences with stop/avoid/do not never create a medicine, details come only from the medicine's own sentence, and a medicine already active is not added again.
- Diagnoses are stored on the consultation record only. They are NOT written to `patient.conditions` (the AI must not edit the medical history).
- Gotcha: a long test run exhausts the Groq daily quota and silently exercises the fallback path. Check `docker compose logs backend | grep -E "RateLimit|used openai"` before trusting a result. Background test scripts must use absolute paths (the shell cwd is not BackEnd).
